## xAI / Grok API URL Extraction — Scrape Method Summary

The method is a **multi-layer cookie injection + authenticated fetch** pipeline, built across several scripts. It evolved iteratively to solve the problem of Edge/Firefox cookie locking.

---

### Architecture (3 layers)

```
Layer 1 — Cookie Harvesting
  Firefox profile  →  cookies.sqlite  (SQLite, copyable while FF is running)
  Edge profile     →  Network/Cookies  (AES-GCM encrypted, locked by Edge process)

Layer 2 — Authentication Bridge
  Firefox cookies  →  injected into fresh Edge/Selenium session  →  x.com domain

Layer 3 — API Interception
  GraphQL fetch to /i/api/graphql/.../GrokShare  →  captures Bearer + response body
```

---

### Script Roles

| Script | Purpose |
|--------|---------|
| capture_grok_bearer.py | **Primary method.** Reads Firefox `cookies.sqlite`, seeds them into a fresh Edge Selenium session, then fires an async `fetch()` JS call to the `GrokShare` GraphQL endpoint to capture the bearer token and full response |
| scrape_grok_auth.py | **Edge-native alternative.** Decrypts Edge's own AES-GCM cookies via DPAPI + `win32crypt`, then performs direct `requests` HTTP calls using the decrypted `auth_token` + `ct0` |
| scrape_grok_ff_inject.py | **Per-share-ID scraper.** Same Firefox→Edge injection approach as capture_grok_bearer.py but targeted at a specific `grok/share/<id>` URL to pull full thread HTML/text |

---

### Core Technical Steps

1. **Copy Firefox's `cookies.sqlite`** to a temp path (avoids read-lock)
2. Query `moz_cookies` for `host LIKE '%.x.com%'` — extracts `auth_token`, `ct0`, and all other session cookies
3. Launch Edge via Selenium with a **fresh/blank profile** (no lock conflict)
4. Navigate to `https://x.com/robots.txt` to establish the domain
5. **Inject all Firefox cookies** into the Edge session
6. Navigate to the target `x.com/i/grok/share/<ID>` URL
7. Execute an `execute_async_script()` JavaScript `fetch()` call to:
   ```
   /i/api/graphql/3aCm_HRrYXX8T7sas50Zlw/GrokShare
     ?variables={"grok_share_id":"<ID>"}
     &features={...}
   ```
   with headers: `x-csrf-token: <ct0>`, `credentials: include`
8. Return the raw JSON response body (contains full conversation)

---

### Diagnostic/Utility Scripts

| Script | What it checks |
|--------|---------------|
| _check_cookie_expiry.py | Validates `auth_token` and `ct0` are not expired (compares epoch vs `time.time()`) |
| _check_cookie_attrs.py | Inspects `httpOnly`, `secure`, `sameSite` attributes to diagnose injection failures |
| _check_cookie_schema.py | Reads Edge's locked `Network/Cookies` DB via `kernel32.CreateFileW` with `FILE_SHARE_READ|WRITE|DELETE` flags (bypasses the lock) and prints the schema |
| _test_cookie_uri.py | Tests SQLite URI modes (`?mode=ro&nolock=1`, `?immutable=1`) as alternative methods to read the locked Edge DB without `ctypes` |
| _read_ff_ls.py | Reads Firefox's `localStorage` SQLite DB for `x.com` (supplementary session data) |
| check_edge_xcom.py | Scans all Edge profiles (`Default`, `Profile *`) for x.com/twitter cookies |

---

### Key API Endpoint

```
GET https://x.com/i/api/graphql/3aCm_HRrYXX8T7sas50Zlw/GrokShare
    ?variables={"grok_share_id":"<32-char-hex-ID>"}
    &features={"premium_content_api_read_enabled":false,...}
Headers:
    x-csrf-token: <ct0 cookie value>
    credentials: include
```

The **CSRF token (`ct0`)** is the critical authentication factor — it must match the active session cookie. The `auth_token` cookie provides the session identity. Both are harvested from Firefox's unencrypted `cookies.sqlite`.
